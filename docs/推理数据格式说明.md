# 洪析先知推理数据格式说明

## 1. 推理输入不是单张普通图片

当前模型使用一个 GFF 空间瓦片的灾前 Sentinel-1 SAR、地形和发布时刻之前的
气象水文信息，预测未来 24、48 或 72 小时的新增（暂态）洪水范围。

用户在界面中选择 `*-s1.tif` 场景文件后，程序会使用元数据和 GeoPackage 中的
瓦片边界，自动读取同一空间范围的其他输入。不能用 PNG、JPEG 或脱离 GFF 目录的
单独 GeoTIFF 替代。

## 2. 必需目录结构

将 GFF 数据放在仓库的 `data/gff` 下：

```text
data/gff/
├── normalisation/
│   ├── s1_norm_0.csv
│   ├── dem_norm_0.csv
│   ├── hand_norm_0.csv
│   ├── glofas_norm_0.csv
│   ├── era5_norm.csv
│   └── era5_land_norm.csv
├── partitions/
│   ├── floodmap_partition_0.txt
│   ├── floodmap_partition_1.txt
│   ├── floodmap_partition_2.txt
│   ├── floodmap_partition_3.txt
│   └── floodmap_partition_4.txt
└── rois/
    ├── <site>-meta.json
    ├── <visit_tiles>.gpkg
    ├── <floodmap>.tif
    ├── <key>-<pre1_date>-s1.tif
    ├── <site>-dem-local.tif
    ├── <site>-hand.tif
    ├── <site>-era5.nc
    ├── <site>-era5-land.nc
    └── <key>_<post_date>.nc
```

尖括号表示变量，不是文件名中的文字。一个可推理站点必须同时拥有上述 9 类
`rois` 文件；文件之间的实际名称由 `<site>-meta.json` 关联。

## 3. 各文件的用途

| 文件 | 必需内容 | 推理用途 |
|---|---|---|
| `*-meta.json` | `key`、`pre1_date`、`post_date`、`visit_tiles`、`floodmap` | 关联站点的全部组件 |
| `*.gpkg` | 瓦片几何及 `n_background`、`n_permanent_water`、`n_flooded` | 确定每个 224×224 推理瓦片的地理边界 |
| `*-s1.tif` | 两个波段，顺序为 VV、VH | 灾前 SAR 输入 |
| `*-dem-local.tif` | 单波段 DEM | 高程输入 |
| `*-hand.tif` | 单波段 HAND | 距排水面的相对高度输入 |
| `*-era5.nc` | 9 个 ERA5 变量，含 `time/latitude/longitude` 坐标 | 20 天气象序列 |
| `*-era5-land.nc` | 14 个 ERA5-Land 变量 | 20 天地表与土壤序列 |
| `<key>_<post_date>.nc` | `dis24`、`rowe`、`swir` | 20 天水文序列 |
| `<floodmap>.tif` | `0=背景、1=永久水体、2=暂态洪水` | 仅用于有效区域掩膜和结果对照，不输入模型 |
| `normalisation/*.csv` | `band,mean,std` 三列 | 使用训练时相同的标准化参数 |
| `partitions/*.txt` | 每行一个 `*-meta.json` 文件名 | 按官方流域 fold 定位 train/val/test 站点 |

正式权重采用 `fold=0`：test 为 fold 0，val 为 fold 1，train 为 fold 2/3/4。

## 4. 获取数据

GFF v3 数据来自 Zenodo 记录 14184289。仓库下载脚本只下载当前模型所需组件：

```powershell
conda run -n daily --no-capture-output python scripts\download_gff.py `
  --root data\gff `
  --components base glofas dem hand era5 s1 `
  --workers 8 `
  --part-mb 16
```

数据较大，下载器支持断点续传、MD5 校验和安全解压。`base` 组件提供元数据、
标签、GeoPackage、normalisation 和 partitions。

## 5. 推理前校验

```powershell
conda run -n daily --no-capture-output python scripts\validate_inference_dataset.py `
  --root data\gff
```

只校验准备在 UI 中选择的一个 Sentinel-1 场景：

```powershell
conda run -n daily --no-capture-output python scripts\validate_inference_dataset.py `
  --root data\gff `
  --image data\gff\rois\<key>-<pre1_date>-s1.tif
```

退出码为 0 表示格式满足推理要求；非 0 时会列出缺失或不匹配的文件。

## 6. 权重和输出

GitHub Release `inference-v1.0.0` 提供两份正式推理权重，均内含模型配置、参数、
验证集阈值及后处理设置。下载后可放在本地 `weights/` 目录：

| 权重 | 概率后处理 |
|---|---|
| `weights/gff_vit_db_full_finetune_best.pt` | 使用原始门控概率，validation 阈值 0.30 |
| `weights/gff_vit_db_full_finetune_adaptive_best.pt` | 低置信度热力图自适应 min–max，高置信度保留原始概率 |

两者使用相同的数据格式。运行 UI：

```powershell
conda run -n daily --no-capture-output python scripts\run_inference_ui.py
```

选择权重、`rois` 中的 `*-s1.tif` 和预测时效即可。程序会通过元数据和官方
partition 清单自动识别该图像属于 train、val 还是 test，无需用户判断。保存操作会生成
三联组合预览图、`_mask.png` 二值掩膜和 `.json` 推理元数据。

## 7. 自定义数据注意事项

若使用非 GFF 数据，必须转换成完全相同的坐标、变量、时间维度和目录关系，并使用
训练阶段的 normalization 统计量。仅把普通图片改名为 `*-s1.tif` 不会得到有效结果。
业务部署还应接入发布时刻真正可用的 ECMWF/GloFAS 预报，并针对该数据重新训练或
微调；GFF 再分析数据上的 causal 模式主要用于研究性回报实验。
